# ChunkyIdle v1.0.0 Roadmap

This document collects proposed features and behavior for the ChunkyIdle v1.0.0 release. Names and defaults in the configuration examples are suggestions and may change during implementation.

## AFK-aware player activity

Add configurable AFK detection so server owners can decide when an online player should count as inactive for ChunkyIdle's generation management.

### Detection source

Provide a setting to choose one AFK detection source:

- **Native:** ChunkyIdle tracks player activity itself. A player becomes AFK after the configured inactivity timeout.
- **AfkPlus:** ChunkyIdle reads the player's AFK state from AfkPlus when that mod is installed and supported. The intended scope includes the Fabric mod and a planned NeoForge port/fork.

The native detector remains available without AfkPlus. If AfkPlus is selected but unavailable, ChunkyIdle should clearly report the problem and use a documented fallback behavior.

### Proposed configuration

The project currently uses YAML configuration. This example follows its existing naming style; exact keys and defaults are to be decided:

```yaml
afk:
  # Select native detection or AfkPlus integration.
  detection-source: native

  # How long without activity before a player is considered AFK (native only).
  time-before-afk: 5m

  # Delay before generation resumes when no active players remain.
  wait-after-afk: 30s

  # Whether an AFK state change can resume generation paused by ChunkyIdle.
  resume-when-afk: true
```

### Intended behavior

- AFK players are distinguished from active players when deciding whether generation should remain paused or may resume.
- `wait-after-afk` is analogous to the existing `automation.wait-after-empty` delay. It begins when no active players remain; if a player becomes active before it expires, the pending resume is cancelled.
- The resume option applies only to tasks ChunkyIdle is allowed to manage. It must not override an administrator's manual pause.
- The AFK detector and the action taken on AFK transitions are separate settings, so either detection source can be used with the same policy.
- Document the interaction between `wait-after-empty` and `wait-after-afk`, including which delay applies when the server becomes empty versus when online players become AFK.

### AfkPlus compatibility

- Integrate through a supported API or small adapter where possible, rather than coupling ChunkyIdle to fork internals.
- Keep the integration optional so servers without AfkPlus can use native detection.
- Plan and document the NeoForge AfkPlus fork/port as a compatibility dependency; it is a separate deliverable from ChunkyIdle's built-in detector.

## Release follow-up

- Finalize setting names, defaults, fallback behavior, and the exact meaning of resume-on-AFK.
- Verify native activity tracking and both detector sources on supported loaders.
- Update configuration documentation and troubleshooting guidance for missing or unsupported AfkPlus versions.
